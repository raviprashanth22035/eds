NFL Events Hub — high-level system design

Static path

Every fan, one portal

  1. 1Resolve. Web, NFL OnePass and the NFL App open the hub on an nfl.com subdomain (e.g. event.nfl.com, proposed); apps use a WebView.
  2. 2Edge. Every request lands on the CDN: cache, WAF, bot rules, and a waiting room for peak registration openings.
  3. 3Origin on miss. Pages, events.json (all events, filters, search) and status come from AEM Edge Delivery. Most traffic stops at the cache.
  4. 4Publish. Clubs and the league author in AEM; publishing purges the CDN in seconds (cancellations included).

Dynamic path

Only signed-in actions

  1. 5Route. The CDN sends only /auth/* and /api/* to the Edge BFF; everything else stays static.
  2. 6Sign in. The BFF runs OIDC with NFL ID (OnePass hands its session to the WebView) and sets an HttpOnly cookie.
  3. 7Register. The BFF forwards register / my events to the OnePass registration API with the fan’s identity.
  4. 8Store. The API enforces capacity and one-per-fan (an adult 18+ can add up to 5 minors, as OnePass does today), stores the registration, issues the QR and wallet pass.
  5. 9Notify. Confirmations and cancellations go on a queue; the notifications worker sends email and push.

Exit

Paid events

  1. 10Buy. Paid events link out to Ticketmaster (VIP via On Location); no payments in the hub.
