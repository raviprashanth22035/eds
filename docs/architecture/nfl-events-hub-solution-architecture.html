NFL Events Hub — solution architecture

01Summary

The Events Hub is a set of fast, cached event sites on AEM Edge Delivery Services (EDS), authored by clubs and the league, shown on nfl.com, club sites, the NFL app and OnePass. A thin edge middleware owns the signed-in session with NFL ID and forwards the few per-fan calls (register, my events). NFL’s own systems stay the source of truth for identity, registrations, notifications and ticketing. The hub never takes payments: paid events link out.

  • Static first. Anything the same for every fan is an EDS page or JSON from the CDN.
  • Direct by default. The browser talks to EDS, the CDN, push and ticket links directly. The middleware is used only for session and secrets.
  • Thin middleware. Edge worker, no database, no page rendering, no business rules beyond auth and forwarding.
  • NFL owns the data. Registrations, capacity, QR validity and fan contact live in NFL services, not in EDS or the worker.
  • No money in the hub. No prices as data, no card forms. Buy = exit link.
  • One build, many surfaces. Same pages for web, embeds and in-app (app mode).

04Key flows

  1. Browse. Fan opens hub or event page → CDN serves cached EDS HTML; listings read events.json (query index); status banner reads status.json.
  2. Log in / Register account. Button → /auth/login or /auth/signup → id.nfl.com → back to /auth/callback → middleware sets session cookie. Already signed in on nfl.com = no prompt. In apps: the app hands over its session (one-time code) — no second login.
  3. Register for an event (free). Register → form block (fields from the event’s sheet) → POST /api/register → registration svc checks capacity and rules → confirmation, status and QR.
  4. Buy tickets (paid). Buy Tickets → authored provider URL in a new tab. Nothing stored in the hub.
  5. My events. /api/my-events → registered events, live status, QR, Add to Wallet (signed pass from the registration service).
  6. Entry. The fan shows the QR (or wallet pass) at the venue; it is validated against the registration service.
  7. Cancellation. Authors mark the event (or every event in a city) cancelled in the status sheet and publish → CDN purged → every page and listing shows it within seconds; the registration service emails / pushes registered fans.
  8. Inside OnePass and embeds. OnePass opens the hub in a WebView with a one-time sign-in code; the middleware turns it into a hub session. Same URLs in app mode (no site chrome, native share/back/wallet via JS bridge) or embed mode on nfl.com and club sites; login from an embed opens id.nfl.com top-level.

07Non-functional

  • Scale. Spikes (registration opening, Draft and Super Bowl week) hit the CDN cache; only per-fan calls reach the middleware. Rate-limit and queue /api/register; load-test it before peak events.
  • Performance. EDS pages target Lighthouse 100; personalization loads after first paint.
  • Security. Tokens never in the browser; HttpOnly, Secure, SameSite cookies; secrets only in the worker.
  • Privacy. International events mean GDPR and local rules: consent for push and email, minimal form fields, data stays in NFL systems.
  • Localization. Site per market/language from one codebase.
  • Accessibility. WCAG 2.2 AA blocks; QR also available as a code fans can read out.
  • Embeds. Allow-list embedding domains; logged-in features open top-level because browsers block third-party cookies.

09Open questions

  1. OnePass registration API access for the hub: register, my events, QR, wallet pass, capacity and status.
  2. Can the hub be registered with NFL ID (Gigya site group or OIDC client), and can OnePass hand over its session to the WebView (getAuthCode / one-time code)?
  3. OnePass WebView support: JS bridge for back, share, wallet; deep links from OnePass screens to hub pages.
  4. Production domain: event.nfl.com (already used for club events) or another nfl.com subdomain.
  5. Must QR codes work with existing OnePass / Leap scanners at venues?
  6. Which notification channel (email, app push) should alert registrants about cancellations?
  7. Wallet: does NFL have Apple pass-type and Google issuer accounts?
  8. Exact ticket URLs and providers for the paid POC events.
  9. Authoring choice (documents vs Universal Editor) and per-club permissions.
  10. CDN choice for production (BYO CDN with edge worker vs AEM Edge Functions).
