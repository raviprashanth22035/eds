NFL Events Hub — high-level design

  1. Clients. NFL OnePass and the NFL App open the hub in a WebView; the web is nfl.com and club sites. One portal for all three.
  2. Edge. DNS → CDN. The CDN serves cached pages to everyone and sends only /auth and /api to the edge worker.
  3. What we build: events.nfl.com. The NFL Events Hub on AEM Edge Delivery (authored by clubs and the league) and a thin, stateless edge worker. No database of ours.
  4. NFL systems (existing). The edge worker calls NFL ID and the registration service (QR, status, wallet) through NFL’s API gateway if one exists; no extra API layer is built.
  5. Personalization. A personalization block in every page uses the AEP Web SDK (EDS martech plugin) to reach the Adobe Edge Network: Adobe Target picks offers, Real-Time CDP supplies profiles and audiences. Browser-direct, after first paint, consent-gated.
  6. Messaging. Registration events (registered, cancelled) stream into AEP: Journey Optimizer sends real-time journeys (confirmation, cancellation alert, reminder, push); Adobe Campaign sends batch email to Real-Time CDP audiences.
  7. Partners. Paid events link out to Ticketmaster (VIP via On Location). No payments in the hub.
  8. Operations. GitHub → code sync → preview → live; WAF and bot rules at the CDN; AEM telemetry and logs. Nothing to provision and no fan data stored by the hub.
